# 몸기록 UI/UX 리팩토링 실행 계획

작성 기준일: 2026-08-06

이 문서는 현재 구현된 화면의 누락을 찾고, 서비스 흐름과 시각 언어를 실제 출시 가능한 수준으로 통일하기 위한 다음 작업 순서다. API 연결은 현재 범위에서 제외한다. 모든 기능은 기존 `wellnessApi` 목업 계약을 유지하며 화면·상태·동선부터 완성한다.

출시까지 필요한 건강 데이터·알림·이미지·백엔드·보안·스토어 작업의 전체 순서는 `MASTER_ROADMAP.md`를 따른다.

## 1. 현재 판단

### 유지할 것

- 홈 / 기록 / 커넥션 뷰 / 챗 / 마이의 5탭 구조
- React Native 네이티브 화면, Expo Router, Safe Area, 공통 뒤로가기
- 전신 근육 바디맵과 부위 선택
- 수면 자세 선택, 기록 캘린더, 차트 애니메이션
- 루틴 실행 타이머, 효과 피드백, 지속 신호, 전문가용 요약 흐름
- 화면과 데이터를 분리한 `wellnessApi` 인터페이스

### 현재 문제

- 화면별로 배경색, 카드 반경, 여백, 제목 크기, 버튼 형태가 달라 한 서비스처럼 보이지 않는다.
- 일부 화면은 큰 카드가 반복돼 정보 밀도가 낮고 전형적인 생성형 UI 인상이 난다.
- 상세·설정 화면은 메인 탭보다 컴포넌트 완성도가 낮고 화면 간 연결감이 약하다.
- 긴 콘텐츠, 키보드, 하단 탭, 고정 CTA가 겹칠 가능성이 있다.
- 작은 화면·큰 글자·긴 문구·빈 데이터에서 레이아웃 안전성이 충분히 검증되지 않았다.
- 로딩·빈 상태·오류·권한 거부가 공통 컴포넌트로 존재해도 실제 관련 화면에 모두 적용되지는 않았다.
- 페이지 명세와 실제 라우트·파일명이 일부 다르며 오래된 완료 체크가 남아 있다.

## 2. 디자인 방향

- 기본 배경은 흰색으로 통일한다.
- 초록은 핵심 행동·선택·상태 강조에만 사용하고 넓은 장식 면에는 남용하지 않는다.
- 빨강·주황은 통증, 경고, 주의가 필요한 상태에서만 사용한다.
- 카드보다 구분선과 섹션 간격을 우선해 정보 구조를 만든다.
- 한 화면의 핵심 CTA는 하나로 제한하고 보조 행동은 텍스트 또는 외곽선 버튼으로 낮춘다.
- 장식용 문구보다 사용자가 방금 기록한 사실, 변화, 다음 행동을 먼저 보여준다.
- 아이콘은 현재 `AppIcon` 체계를 사용하고 이모지·서로 다른 선 굵기·임의 도형을 섞지 않는다.
- 모션은 진입 이해, 상태 변화, 선택 피드백에만 사용하며 짧고 중단 가능하게 만든다.
- 모든 터치 영역은 최소 44pt, 본문은 큰 글자에서도 잘리거나 겹치지 않아야 한다.

## 3. 순차 작업 계획

### 1단계 — 전체 화면 인벤토리와 누락 판정

- [ ] `src/app`의 모든 라우트를 실제 기기 또는 시뮬레이터에서 순서대로 연다.
- [ ] 최종 PDF의 기능·화면과 현재 라우트를 1:1로 대조한다.
- [ ] 각 화면을 `완료 / 리팩토링 / 상태 누락 / 화면 누락 / 제거 후보`로 판정한다.
- [ ] `PAGE_SPEC.md`의 오래된 라우트명과 실제 구현을 일치시킨다.
- [ ] 개발용 `/explore`, `/empty-states`가 출시 앱에 노출되는지 확인하고 용도를 정한다.
- [ ] 화면별 캡처와 문제를 체크리스트에 남긴다.

완료 조건: 구현된 모든 라우트에 판정과 수정 항목이 하나 이상 연결되고, PDF에 있지만 라우트가 없는 항목이 명시된다.

### 2단계 — 디자인 시스템 재정리

- [ ] 흰색 배경, 텍스트, 보조 텍스트, 경계선, 초록, 통증, 경고 색상 역할을 확정한다.
- [ ] 제목·섹션 제목·본문·보조 문구·수치의 타이포 계층을 5~6개로 제한한다.
- [ ] 화면 좌우 여백, 섹션 간격, 행 높이, 카드 반경, 버튼 높이 규칙을 확정한다.
- [ ] `Screen`, `PageHeader`, `FixedCTA`, `ListSection`, `ListRow`, `Field`, `StatusBadge` 공통 구조를 정리한다.
- [ ] 눌림·선택·비활성·로딩·오류 상태의 피드백을 통일한다.
- [ ] 페이지 전용 스타일에 중복된 색상·간격·반경을 토큰으로 이동한다.

완료 조건: 새 화면을 임의 값 없이 조합할 수 있고, 같은 역할의 요소가 화면마다 다른 모양으로 나타나지 않는다.

### 3단계 — 앱 셸과 공통 UX

- [ ] 5개 하단 탭의 높이, Safe Area, 활성 상태, 라벨 줄바꿈을 통일한다.
- [ ] 탭 화면과 상세 화면의 상단 헤더 규칙을 분리해 일관되게 적용한다.
- [ ] 뒤로가기 시 입력 내용이 있으면 이탈 확인, 없으면 즉시 이전 화면으로 이동한다.
- [ ] 키보드가 챗 입력창·폼 필드·고정 CTA를 가리지 않도록 공통 처리한다.
- [ ] ScrollView 하단 여백을 탭바·CTA·Safe Area 기준으로 계산한다.
- [ ] 화면 전환, 바텀시트, 선택 상태의 모션 속도와 감속 규칙을 통일한다.

완료 조건: 어떤 화면에서도 탭바·키보드·CTA가 콘텐츠를 가리지 않고 뒤로가기 동작이 예측 가능하다.

### 4단계 — 인증·온보딩 리디자인

대상: 스플래시, 로그인, 회원가입, 서비스 안내, 민감정보 동의, 기본 상태 설정, 건강 데이터 연결

- [ ] 스플래시부터 로그인까지 브랜드 인상이 자연스럽게 이어지도록 재구성한다.
- [ ] 로그인·회원가입 폼의 라벨, 오류, 비밀번호 보기, 비활성 CTA를 통일한다.
- [ ] 온보딩 진행률과 뒤로가기·건너뛰기 정책을 명확히 한다.
- [ ] 동의 항목의 수집 내용·목적·보관 기간·철회 방법을 펼쳐 볼 수 있게 한다.
- [ ] 기본 상태 입력을 한 화면에 과밀하게 배치하지 않고 의미 단위로 나눈다.
- [ ] 건강 데이터 제공자를 독립 행 또는 카드로 구분하고 연결 전·연결 중·연결 완료·실패 상태를 만든다.

완료 조건: 신규 사용자가 설명 없이도 가입 → 동의 → 기본 상태 → 연결 선택 → 홈까지 중단 없이 진행할 수 있다.

### 5단계 — 홈·데일리 체크 리디자인

대상: 홈, 자동 데이터, 컨디션, 수면, 불편 부위, 활동·피부, 기록 완료

- [ ] 홈의 정보 우선순위를 `오늘 상태 → 전신 기록 → 오늘 할 일 → 최근 변화`로 재검토한다.
- [ ] 전신 바디맵은 전신이 한눈에 보이면서 활성 근육만 누를 수 있고 터치 영역은 충분히 확보한다.
- [ ] 바디맵 선택 결과와 기록하기의 초기 부위가 동일하게 연결되는지 확인한다.
- [ ] 홈의 카드 수와 장식 면적을 줄이고 기록 사실과 다음 행동을 선명하게 만든다.
- [ ] 데일리 체크 전체 단계에 동일한 진행 표시, 질문 형식, 선택 카드, 하단 CTA를 적용한다.
- [ ] 수면 자세 일러스트의 방향·선 굵기·선택 상태를 통일한다.
- [ ] 앞·뒤 바디맵, 좌우 부위, 복수 선택, 부위별 강도·느낌의 수정 흐름을 검증한다.
- [ ] 피부 촬영·앨범·사진 제거·상태만 기록·건너뛰기 동선을 정리한다.
- [ ] 기록 완료에서 요약을 확인하고 원하는 단계로 돌아가 수정할 수 있게 한다.

완료 조건: 홈에서 부위 선택 → 기록 시작 → 단계별 입력 → 완료 → 수정 → 홈 반영 흐름이 자연스럽고 모든 선택이 시각적으로 명확하다.

### 6단계 — 기록·커넥션 뷰 리디자인

대상: 기록 캘린더, 날짜별 상세, 커넥션 뷰, 패턴 상세

- [ ] 캘린더에서 오늘·선택일·기록 있음·기록 없음의 의미를 색상만으로 구분하지 않는다.
- [ ] 날짜 상세를 수면·불편·피부·활동·루틴·피드백의 일정한 섹션 순서로 정리한다.
- [ ] 커넥션 뷰 상단의 기간 선택과 개인 기준선을 작은 화면에서도 한눈에 읽히게 한다.
- [ ] 지표 선택은 최대 3개 제한과 선택 색상을 즉시 이해할 수 있게 한다.
- [ ] 차트 범례·축·날짜·선택 지점을 정돈하고 진입 애니메이션 후 조작성을 유지한다.
- [ ] 차트 날짜 선택 상세가 탭바에 가리지 않고 스와이프 또는 명시적 닫기로 종료되게 한다.
- [ ] 패턴 상세에서 근거 → 해석 → 권장 행동 → 관련 기록 순서가 유지되게 한다.
- [ ] 홈·커넥션 뷰·기록 상세에 전문가용 요약 진입점을 빠짐없이 배치한다.

완료 조건: 사용자가 특정 날짜 기록과 기간 패턴을 혼동하지 않고, 차트에서 근거 기록까지 두 번 이내의 행동으로 확인할 수 있다.

### 7단계 — 루틴·피드백·지속 신호 리디자인

대상: 오늘의 루틴, 루틴 실행, 완료, 효과 피드백, 지속 신호

- [ ] 루틴 추천 이유, 예상 시간, 강도, 단계 수를 실행 전에 명확히 보여준다.
- [ ] 타이머의 진행·일시정지·건너뛰기·중단을 엄지 영역에서 조작 가능하게 한다.
- [ ] 중단 확인과 완료 화면이 브라우저식 경고창에만 의존하지 않도록 검토한다.
- [ ] 완료 후 즉시 피드백과 다음 날 확인이 서로 다른 질문임을 구분한다.
- [ ] 악화 피드백은 사용자를 불안하게 만들지 않으면서 중단·관찰·상담 기준을 안내한다.
- [ ] 지속 신호는 진단처럼 보이지 않게 기록 근거, 반복 기간, 권장 행동, 요약 만들기를 제공한다.
- [ ] 지속 신호와 챗·요약 카드로 이동한 뒤 돌아오는 흐름을 확인한다.

완료 조건: 루틴 시작부터 종료·피드백까지 한 손 조작이 가능하고 안전 안내가 행동을 방해하지 않으면서 눈에 띈다.

### 8단계 — 챗·요약 카드 리디자인

대상: 웰니스 챗, 요약 설정, 요약 미리보기

- [ ] 챗 입력창을 키보드와 하단 탭 위에 고정하고 메시지 목록이 가려지지 않게 한다.
- [ ] 첫 화면의 과도한 빈 공간을 줄이고 추천 질문과 입력 행동을 가까이 배치한다.
- [ ] 사용자·웰니스 챗 메시지의 위계를 색칠된 큰 말풍선보다 정돈된 대화 구조로 만든다.
- [ ] `참고한 내 기록`, 공식 의약품 정보, 안전 안내, 관련 화면 CTA의 시각 계층을 통일한다.
- [ ] 사진 첨부·전송 중·응답 생성 중·실패 재전송 상태를 완성한다.
- [ ] 요약 설정의 기간·포함 항목·개인정보 숨기기를 짧은 단계로 이해하게 만든다.
- [ ] 전문가 모드는 화면을 건네 보여주기 쉬운 밀도와 큰 핵심 수치로 재구성한다.
- [ ] 이미지 저장·복사·공유 완료 피드백과 실패 상태를 만든다.
- [ ] 챗 화면에도 전문가용 요약 진입점을 제공한다.

완료 조건: 작은 iPhone에서 키보드를 연 상태로 입력·첨부·전송이 가능하고, 요약 카드의 일반 보기와 전문가 보기가 목적에 맞게 구분된다.

### 9단계 — 마이·전체 설정 리디자인

대상: 마이, 건강 데이터, 알림, 동의·데이터 관리, 계정 관리, 서비스 정보·문의

- [ ] 마이를 거대한 프로필 카드 중심이 아닌 계정 요약과 설정 목록 중심으로 재구성한다.
- [ ] 메뉴 행의 아이콘, 라벨, 상태값, 화살표, 구분선을 동일한 규칙으로 맞춘다.
- [ ] 건강 데이터의 제공자·권한 항목·마지막 동기화·연결 해제를 구분한다.
- [ ] 알림 종류와 기록 알림 시간을 그룹화하고 저장 방식과 변경 완료 피드백을 명확히 한다.
- [ ] 동의 상태, 보관 정보, 내 데이터 작업, 위험 작업을 서로 다른 섹션으로 분리한다.
- [ ] 데이터 삭제는 피부 사진·기간 기록·전체 데이터마다 대상과 복구 불가 여부를 확인시킨다.
- [ ] 계정 폼의 키보드, 유효성, 오류 문구, 버튼 활성화를 정리한다.
- [ ] 약관·개인정보처리방침·문의 화면이 단순 경고창이 아니라 읽고 실행 가능한 화면인지 확인한다.

완료 조건: 모든 설정 화면이 같은 목록·폼·위험 행동 규칙을 사용하고, 저장·실패·취소 결과가 명확하다.

### 10단계 — 빈 상태·예외·접근성 적용

- [ ] 기준선 14일 미완성 상태를 홈과 커넥션 뷰에 실제 적용한다.
- [ ] 오늘 기록을 놓친 상태와 과거 날짜 기록 유도 문구를 기록 화면에 적용한다.
- [ ] 자동 건강 데이터 연결 실패 시 다시 시도·직접 입력·설정 이동을 제공한다.
- [ ] 패턴 관계가 낮거나 기록이 부족한 상태를 커넥션 뷰와 패턴 상세에 적용한다.
- [ ] 챗이 기록과 무관한 질문에 답하지 못하는 상태와 안전 안내를 적용한다.
- [ ] 네트워크 오류·저장 실패·권한 거부·사진 실패·공유 실패를 관련 화면에서 재현한다.
- [ ] VoiceOver/TalkBack 읽기 순서, 접근성 라벨, 동적 글자 크기, 명도 대비를 확인한다.

완료 조건: 정상 데이터가 없어도 막다른 화면이 없고, 모든 예외 상태에서 사용자가 다음 행동을 선택할 수 있다.

### 11단계 — 전 화면 실기기 QA와 문서 정리

- [ ] 작은 iPhone, Dynamic Island iPhone, 대표 Android 크기에서 전 라우트를 확인한다.
- [ ] 큰 글자, 긴 이름, 긴 날짜, 키보드, 저속 애니메이션 환경을 확인한다.
- [ ] 스크롤 잘림, 탭바 겹침, CTA 겹침, 가로 넘침, 터치 불가 영역을 제거한다.
- [ ] 홈 바디맵, 커넥션 차트, 루틴 타이머, 챗 스크롤의 체감 성능을 확인한다.
- [ ] 화면 캡처를 최종 PDF와 비교하고 남은 차이는 문서에 기록한다.
- [ ] `PAGE_SPEC.md`, `FINAL_FUNCTION_AUDIT.md`, `IMPLEMENTATION_CHECKLIST.md`를 실제 결과 기준으로 갱신한다.

완료 조건: 모든 출시 라우트의 정상·빈·오류 상태가 실기기에서 검수되고 문서의 체크 상태가 코드와 일치한다.

## 4. 바로 시작할 작업

API 작업은 보류한다. 다음 작업은 `1단계 — 전체 화면 인벤토리와 누락 판정`부터 시작한다.

첫 작업 결과물은 다음 세 가지다.

1. 전체 라우트별 UI/UX 문제 목록
2. 최종 PDF 대비 실제 누락 화면·상태 목록
3. 공통 수정과 화면별 수정으로 나눈 우선순위 백로그

그다음 `2단계 — 디자인 시스템 재정리`, `3단계 — 앱 셸과 공통 UX`를 먼저 적용한 뒤 인증 화면부터 마이·설정까지 순차적으로 리팩토링한다. 공통 기반을 확정하지 않은 상태에서 개별 화면 색상과 카드만 다시 손보지 않는다.

## 5. 문서 우선순위

UI/UX 판단이 충돌할 때는 아래 순서를 따른다.

1. 최종 기능 및 UI 설계 명세 PDF
2. `NEXT_STEPS.md`
3. 실제 실기기 화면과 사용 흐름
4. `FINAL_FUNCTION_AUDIT.md`
5. `PAGE_SPEC.md`, `IMPLEMENTATION_CHECKLIST.md`, `WORK_HANDOFF.md`

과거 문서의 `[x]`는 화면 파일 또는 기능 골격이 존재한다는 뜻일 수 있으며, UI/UX 리팩토링과 실기기 검수가 끝났다는 뜻은 아니다.
