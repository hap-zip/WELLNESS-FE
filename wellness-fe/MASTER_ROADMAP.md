# 몸기록 제품 완성 마스터 로드맵

작성 기준일: 2026-08-06

이 문서는 현시점부터 앱 출시와 초기 운영까지 필요한 작업을 추적한다. UI의 유일한 시각 기준은 `REDESIGN_V3.md`, 실행 상태는 `NEXT_STEPS.md`, API 목록은 `API_SPEC.md`에서 관리한다.

## 1. 현재 프로젝트 상태

### 구현된 것

- 인증·온보딩·홈·데일리 체크·기록·커넥션 뷰·루틴·피드백·지속 신호·요약·챗·마이·설정 화면
- 5개 하단 탭과 주요 상세 화면 라우팅
- 바디맵, 수면 자세 선택, 캘린더, 애니메이션 차트, 루틴 타이머
- 카메라·앨범 선택, 요약 이미지 저장·공유의 화면 흐름
- 실제 API로 교체 가능한 `wellnessApi` 인터페이스와 목업 데이터

### 아직 준비되지 않은 것

- 전체 화면 UI/UX 통일과 전 라우트 실기기 검수
- 실제 인증·서버 데이터·파일 업로드 연결
- Apple HealthKit·Android Health Connect 실제 연동
- 로컬·원격 푸시 알림과 알림 딥링크
- 토큰 보안 저장, 개발·스테이징·운영 환경 분리
- EAS Development·Preview·Production 빌드 설정
- 자동화 테스트, 오류 모니터링, 분석 이벤트
- 개인정보·건강정보 정책과 스토어 심사 자료
- 앱 이름, Bundle ID·Package name, 아이콘, 스플래시, 스토어 자산 확정

현재 `app.json`에는 카메라·사진·미디어 저장 권한 설명만 일부 등록돼 있다. `expo-notifications`, SecureStore, HealthKit·Health Connect 모듈, `eas.json`, 환경 파일은 아직 없다.

## 2. 전체 진행 순서

아래 작업 패키지는 의존 관계 순서다. 한 패키지 안에서는 묶어서 진행하되 완료 조건을 충족하기 전 다음 패키지의 본 구현으로 넘어가지 않는다.

1. 제품 기준과 디자인 완성
2. 앱 식별자·개발 빌드·환경 기반
3. 권한·기기 기능 공통 기반
4. 건강 데이터·알림·이미지 네이티브 기능
5. 백엔드·인증·동기화
6. 챗·패턴·전문가 요약 안전성
7. 개인정보·보안·운영 도구
8. 전 플랫폼 QA·스토어 출시

## 3. 작업 패키지 A — 제품 기준과 UI/UX 완성

API 연결 전에 끝내야 하는 현재 최우선 작업이다.

### A-1. 기능·화면 누락 점검

- [ ] 최종 PDF와 `src/app` 전체 라우트를 1:1 대조한다.
- [ ] 모든 화면을 완료·리팩토링·상태 누락·화면 누락·제거 후보로 분류한다.
- [ ] 홈부터 설정 상세까지 정상·빈·오류·권한 거부 상태를 정의한다.
- [ ] 개발 전용 화면이 출시 앱에 노출되지 않도록 구분한다.

### A-2. 디자인 시스템

- [x] V2 디자인 기준을 폐기하고 V3 Editorial Ledger 방향을 문서화한다.

- [ ] 채팅 말풍선·히어로 카드·반복 라운드 카드가 전 라우트에서 제거됐는지 검사한다.

### A-3. 전 화면 순차 전면 교체

- [ ] 앱 셸·하단 탭·헤더·뒤로가기·키보드·Safe Area

- [ ] 업그레이드할 경우 Expo 57 버전 문서와 호환표를 기준으로 전체 의존성을 맞춘다.

### B-3. 환경 분리

- [ ] 개발·스테이징·운영 API 주소와 기능 플래그를 분리한다.
- [ ] 공개 가능한 설정과 비밀 키를 구분한다.

완료 조건: 개발·스테이징 앱이 별도로 설치되고, 네이티브 모듈 변경 후 팀이 재현 가능한 방식으로 빌드할 수 있다.

## 5. 작업 패키지 C — 권한과 기기 기능 공통 UX

HealthKit, 알림, 카메라를 각각 임의로 구현하지 않고 같은 권한 패턴으로 묶는다.

- [ ] 권한 요청 전 서비스 내 사전 설명 화면을 제공한다.
- [ ] OS 권한 상태를 미요청·허용·일부 허용·거부·재요청 불가로 모델링한다.
- [ ] 권한을 실제 기능을 처음 사용할 때 요청한다.
- [ ] 거부 후 다시 시도와 시스템 설정 이동을 제공한다.
- [ ] 앱이 포그라운드로 돌아올 때 권한 상태를 다시 확인한다.
- [ ] 카메라·사진·건강 데이터·알림의 목적 문구를 한국어로 확정한다.
- [ ] 권한이 없어도 직접 입력 등 가능한 대체 경로를 유지한다.
- [ ] 권한 상태와 서비스 내부 토글이 서로 다를 때 정확한 안내를 표시한다.

완료 조건: 사용자가 어떤 권한을 거부해도 앱이 막히지 않고, 설정에서 권한을 바꾼 뒤 앱 상태가 즉시 갱신된다.

## 6. 작업 패키지 D — 네이티브 기능

### D-1. Apple 건강·Android 건강 데이터

프론트 네이티브 영역과 백엔드 영역을 구분한다.

#### 앱에서 처리

- [ ] iOS HealthKit Capability와 읽기 목적 문구를 설정한다.
- [ ] Android Health Connect 권한과 제공자 상태를 설정한다.
- [ ] 수면·걸음·필요 시 심박 등 최소 데이터 항목을 확정한다.
- [ ] 항목별 읽기 권한을 요청한다.
- [ ] 날짜 범위 조회, 단위 변환, 출처 구분, 중복 방지 식별자를 처리한다.
- [ ] 최초 동기화·증분 동기화·수동 재동기화 흐름을 구현한다.
- [ ] 일부 권한, 데이터 없음, 기기 미지원, 연결 끊김 상태를 구현한다.
- [ ] 직접 입력값과 자동 수집값의 출처를 화면에 구분한다.

#### 백엔드에서 처리

- [ ] 앱이 전달한 최소 건강 데이터만 저장한다.
- [ ] 사용자·날짜·출처·샘플 기준 중복을 제거한다.
- [ ] 개인 기준선, 홈 요약, 차트와 패턴 계산에 사용한다.
- [ ] 동의 철회·연결 해제·회원 탈퇴 시 삭제 정책을 적용한다.
- [ ] 마지막 동기화와 실패 상태를 관리한다.

#### 반드시 결정할 것

- [ ] HealthKit에 데이터를 읽기만 할지 쓰기도 할지 정한다.
- [ ] 원본 샘플을 서버에 저장할지 일별 집계만 저장할지 정한다.
- [ ] 수면 출처가 여러 개일 때 우선순위와 중복 병합 규칙을 정한다.
- [ ] 백그라운드 동기화 필요성과 배터리·심사 영향을 검토한다.

완료 조건: iPhone·Android 실기기에서 권한 → 조회 → 서버 동기화 → 홈·기록 반영 → 연결 해제까지 검증된다.

### D-2. 알림

알림은 발생 기준에 따라 로컬과 원격으로 나눈다.

| 알림 | 권장 방식 | 이유 |
|---|---|---|
| 매일 기록 시간 | 로컬 알림 | 사용자가 정한 반복 시각을 기기에서 처리 가능 |
| 시작해 둔 루틴 리마인드 | 로컬 알림 | 앱 내 행동과 짧은 시간 조건으로 처리 가능 |
| 다음 날 효과 확인 | 로컬 우선, 서버 보완 | 루틴 완료 시 다음 날 예약 가능 |
| 오늘의 추천 루틴 생성 | 원격 알림 | 서버에서 추천 생성 완료 시점에 발송 |
| 주간 기록 요약 | 원격 알림 | 서버 집계 완료 후 발송 |
| 증상 지속 신호 | 원격 알림 | 서버가 여러 날 기록을 분석해 판단 |
| 계정·보안·데이터 처리 | 원격 알림 | 서버 사건을 사용자에게 전달 |

#### 앱에서 처리

- [ ] `expo-notifications` 설치와 config plugin을 설정한다.
- [ ] iOS·Android 알림 권한을 요청하고 상태를 해석한다.
- [ ] Android 알림 채널, 아이콘, 색상, 중요도를 설정한다.
- [ ] 로컬 알림 예약·변경·취소를 구현한다.
- [ ] Expo Push Token 또는 APNs·FCM 토큰 전략을 정하고 토큰을 등록한다.
- [ ] 토큰 변경·로그아웃·탈퇴 시 갱신 또는 해제한다.
- [ ] 포그라운드 표시, 알림 탭, 앱 종료 상태 탭을 처리한다.
- [ ] 알림 종류별 딥링크를 홈·기록·루틴·피드백·지속 신호로 연결한다.
- [ ] OS 권한은 꺼져 있지만 앱 내부 토글은 켜진 불일치를 안내한다.
- [ ] 시간대 변경과 서머타임에도 사용자가 선택한 시각을 유지한다.

#### 백엔드에서 처리

- [ ] 기기 토큰과 플랫폼, 앱 환경, 마지막 사용 시점을 관리한다.
- [ ] 사용자 알림 설정과 방해 금지 시간대를 관리한다.
- [ ] 주간 요약·추천 루틴·지속 신호 발송 작업을 예약한다.
- [ ] 중복 발송 방지와 발송 이력을 관리한다.
- [ ] 만료·실패 토큰을 비활성화한다.
- [ ] 알림함 데이터와 읽음 상태를 관리한다.

완료 조건: 권한 허용·거부, 로컬 예약, 서버 푸시, 딥링크, 토큰 만료, 로그아웃을 iOS와 Android에서 검증한다.

### D-3. 카메라·이미지·파일

- [ ] 피부 사진과 약 포장 사진의 용도·보관 기간·삭제 정책을 분리한다.
- [ ] 촬영·앨범·취소·권한 거부·재촬영 UX를 완성한다.
- [ ] 업로드 전 크기 조정, 방향 보정, 파일 형식과 최대 용량을 확정한다.
- [ ] 민감한 이미지의 메타데이터와 위치정보 제거 여부를 결정한다.
- [ ] 업로드 진행률·재시도·중복 업로드 방지를 구현한다.
- [ ] 비공개 저장소와 만료되는 접근 URL을 사용한다.
- [ ] 썸네일과 원본의 접근 권한을 분리한다.
- [ ] 기록 삭제·사진만 삭제·회원 탈퇴 시 파일까지 삭제한다.
- [ ] 전문가 요약 이미지는 사용자가 명시적으로 저장·공유할 때만 생성한다.

완료 조건: 권한 요청부터 업로드·조회·삭제·공유까지 실패 상태를 포함해 검증되고 외부 공개 URL로 원본에 접근할 수 없다.

## 7. 작업 패키지 E — 백엔드와 데이터 연결

UI와 네이티브 기능의 계약이 확정된 뒤 시작한다.

### E-1. 데이터 모델 확정

- [ ] 통증 점수 범위와 피부·수면 점수 범위를 확정한다.
- [ ] 통증 부위를 콤마 문자열이 아닌 부위·좌우·강도·느낌 단위로 저장한다.
- [ ] 수면 자세, 베개, 불편 느낌, 신호 유형 enum을 확정한다.
- [ ] 사용자 동의 이력, 토큰, 알림, 루틴, 피드백, 이미지, 건강 데이터 테이블을 확정한다.
- [ ] 날짜 기준과 서버·사용자 시간대 처리 규칙을 확정한다.

### E-2. 프론트 통신 기반

- [ ] Mock과 Remote API 구현을 분리한다.
- [ ] 공통 HTTP 클라이언트, 오류 코드, 타임아웃, 재시도를 구현한다.
- [ ] Access Token을 안전하게 저장하고 Refresh Token 갱신을 구현한다.
- [ ] DTO와 화면 도메인 모델 사이 매퍼를 둔다.
- [ ] 서버 연결 중에도 로딩·빈·오류·재시도가 현재 UI 규칙을 유지하게 한다.

### E-3. 실제 연결 순서

- [ ] 인증·계정·동의·온보딩
- [ ] 데일리 체크 저장·수정·삭제
- [ ] 홈·기록 캘린더·날짜 상세
- [ ] 건강 데이터 동기화
- [ ] 루틴·효과 피드백·지속 신호
- [ ] 커넥션 뷰·패턴
- [ ] 전문가 요약·공유
- [ ] 챗·의약품 정보
- [ ] 알림함·설정·데이터 내보내기·탈퇴

완료 조건: 가입부터 기록, 분석, 루틴, 요약, 삭제까지 하나의 테스트 계정으로 실제 서버 데이터가 일관되게 이어진다.

## 8. 작업 패키지 F — 분석·챗·전문가 전달 안전성

- [ ] 패턴과 신호의 계산 기준, 최소 기록 수, 신뢰 단계 문구를 확정한다.
- [ ] 기록이 부족하거나 관계가 낮을 때 억지 패턴을 생성하지 않는다.
- [ ] 챗이 참고한 사용자 기록의 날짜와 항목을 표시한다.
- [ ] 진단·처방으로 오해될 표현과 응급 증상 대응 기준을 정의한다.
- [ ] 약 정보는 공식 출처, 성분, 효능, 주의사항과 개인 복용 판단 제한을 표시한다.
- [ ] 사진 판독 실패와 제품 불일치 가능성을 명확히 알린다.
- [ ] 전문가용 요약은 사용자 선택 기간·항목·개인정보 숨기기를 반영한다.
- [ ] 공유 링크 만료·회수·접근 기록 정책을 확정한다.
- [ ] 생성 결과 신고·피드백·운영 검토 흐름을 마련한다.

완료 조건: 기록 부족, 위험 질문, 약물 질문, 이미지 실패, 공유 만료 사례가 정의된 안전 정책에 따라 처리된다.

## 9. 작업 패키지 G — 개인정보·보안·운영

### G-1. 개인정보와 동의

- [ ] 이용약관·개인정보처리방침·민감정보 동의를 분리한다.
- [ ] 수집 항목·목적·보관 기간·제3자 제공·철회 방법을 실제 동작과 일치시킨다.
- [ ] HealthKit 데이터와 피부 사진을 광고·마케팅 데이터로 사용하지 않는다.
- [ ] 필수·선택 동의를 구분하고 동의 이력을 보관한다.
- [ ] 데이터 내보내기, 기간 삭제, 사진 삭제, 전체 삭제, 탈퇴를 검증한다.

### G-2. 앱·서버 보안

- [ ] 토큰을 일반 스토리지나 로그에 저장하지 않는다.
- [ ] 운영 로그에서 건강정보·채팅·사진 URL·인증정보를 마스킹한다.
- [ ] 이미지 접근 URL에 만료와 권한 검증을 적용한다.
- [ ] 전송 구간 암호화, 서버 저장 암호화, 백업 보존 정책을 확정한다.
- [ ] 탈옥·루팅 탐지의 필요성과 오탐 영향을 검토한다.
- [ ] 의존성 취약점과 비밀 키 유출 검사를 자동화한다.

### G-3. 운영 도구

- [ ] 크래시·네이티브 오류·API 오류 모니터링을 도입한다.
- [ ] 건강정보가 없는 최소 분석 이벤트 체계를 설계한다.
- [ ] 가입·온보딩·기록 완료·루틴 완료·알림 진입의 퍼널을 측정한다.
- [ ] 기능 플래그와 긴급 비활성화 방식을 준비한다.
- [ ] 사용자 문의, 데이터 삭제 요청, 장애 대응 담당과 절차를 정한다.

완료 조건: 개인정보 흐름도가 실제 코드·서버·외부 도구와 일치하고 장애와 삭제 요청을 운영자가 처리할 수 있다.
