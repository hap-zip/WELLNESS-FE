# 하음 캐릭터(체키) 사용 가이드 및 개발 전달 문서

이 문서는 **Claude Code에 그대로 전달할 수 있도록 정리한 단일 문서**입니다.  
현재 확정된 캐릭터 파일 목록과, **어떤 화면/상황에서 어떤 캐릭터를 써야 하는지**를 함께 정리했습니다.

---

## 1. 캐릭터 개요

### 캐릭터명
- **체키**

### 캐릭터 역할
체키는 하음 서비스의 **기록 동반자**입니다.  
사용자를 과하게 들뜨게 만드는 마스코트가 아니라,  
**차분하고 친근하게 기록을 돕고 상태를 안내하는 안내자** 역할을 합니다.

### 캐릭터 인상
- 말랑하고 둥근 실루엣
- 흰색 본체 + 라임색 크로스백(체크 아이콘)
- 부담스럽지 않은 표정
- “귀엽지만 조용한” 톤
- 웰니스/바디 트래킹 서비스와 어울리는 **부드러운 동반자 느낌**

### 사용 원칙
- 캐릭터는 **장식용이 아니라 기능 보조용**으로 사용한다.
- 상태 전달이 필요할 때만 사용한다.
- 한 화면에 너무 많이 반복 노출하지 않는다.
- 복잡한 데이터 화면에서는 메인 정보보다 튀지 않게 보조적으로 사용한다.
- Empty state, onboarding, 가이드, 상태 피드백에 집중해서 쓴다.

## 2. 현재 파일 목록

아래 파일들이 현재 사용 가능한 캐릭터 에셋입니다.

### 기준형 / 베이스
1. `라임_가방을_멘_귀여운_마스코트.png`
   - 가장 기본이 되는 체키 기준형
   - 다른 포즈를 만들 때 기준으로 삼을 메인 캐릭터

2. `라임색_크로스백_마스코트.png`
   - 초기 기준형 시안
   - 가능하면 실제 적용은 `라임_가방을_멘_귀여운_마스코트.png`를 우선 사용

### 상태별 포즈
3. `초록_가방을_멘_귀여운_손인사_캐릭터.png`
   - 인사 / 첫 진입 / 환영

4. `잠든_초록_가방_마스코트.png`
   - 수면 / 휴식 / 회복

5. `어깨_통증을_호소하는_귀여운_마스코트.png`
   - 통증 / 불편 체크

6. `클립보드를_든_귀여운_상담_마스코트.png`
   - 챗 / 가이드 / 안내

7. `메모하는_귀여운_라임_마스코트.png`
   - 기록 작성 / 체크 입력 / 기록 유도

8. `돋보기_든_귀여운_탐정_마스코트.png`
   - 패턴 분석 / 인사이트 / 변화 탐색

## 3. 캐릭터 사용 매핑

아래는 **실제 서비스 화면 기준으로 어떤 캐릭터를 언제 써야 하는지** 정리한 표입니다.

| 상태 키 | 파일명 | 사용 시점 | 추천 화면 |
|---|---|---|---|
| `base` | `라임_가방을_멘_귀여운_마스코트.png` | 기본형이 필요할 때 | 대표 소개, 가이드 문서, 향후 새 상태 제작 기준 |
| `welcome` | `초록_가방을_멘_귀여운_손인사_캐릭터.png` | 첫 진입, 환영, 온보딩, 빈 홈 상태 | 온보딩, 로그인 직후, 초기 홈 |
| `sleep` | `잠든_초록_가방_마스코트.png` | 수면 기록, 회복, 휴식 안내 | 수면 카드, 회복 루틴, 밤/취침 관련 섹션 |

| `chat` | `클립보드를_든_귀여운_상담_마스코트.png` | 챗봇, 가이드, 설명, 코칭 | AI 안내, 루틴 설명, 질문응답 |
| `recording` | `메모하는_귀여운_라임_마스코트.png` | 기록 작성 유도, 직접 입력, 체크리스트 입력 | 기록하기, 데일리 체크, 입력 폼 |
| `insight` | `돋보기_든_귀여운_탐정_마스코트.png` | 패턴 발견, 분석, 변화 해석 | 커넥션, 최근 변화, 인사이트 섹션 |

## 4. 화면별 추천 사용 방식

### A. 온보딩 / 첫 진입
**사용 캐릭터**
- `초록_가방을_멘_귀여운_손인사_캐릭터.png`

**언제 쓰나**
- 사용자가 앱에 처음 들어왔을 때
- 계정 생성 직후
- “하음이 어떤 서비스인지” 설명하는 첫 화면

**추천 문구 예시**
- “안녕하세요, 체키와 함께 오늘의 몸을 기록해보세요.”
- “하루의 몸 상태를 가볍게 남겨보세요.”
- “기록이 쌓이면 내 몸의 패턴이 보이기 시작해요.”

---

### B. 홈 화면 / 기본 Empty State
**사용 캐릭터**
- `초록_가방을_멘_귀여운_손인사_캐릭터.png`
- 또는 베이스 기준형 `라임_가방을_멘_귀여운_마스코트.png`

**언제 쓰나**
- 아직 오늘 기록이 없을 때
- 이번 주 기록이 비어 있을 때
- 커넥션 데이터가 아직 충분하지 않을 때

**추천 문구 예시**
- “오늘의 몸 상태를 기록해볼까요?”
- “기록이 쌓이면 몸의 흐름을 더 잘 볼 수 있어요.”
- “지금 첫 기록을 남겨보세요.”

---

### C. 기록 작성 / 체크 입력
**사용 캐릭터**
- `메모하는_귀여운_라임_마스코트.png`

**언제 쓰나**
- 기록하기 버튼 눌렀을 때
- 직접 입력 폼
- 체크리스트
- 일일 상태 입력 유도

**추천 문구 예시**
- “오늘의 몸 상태를 간단히 남겨주세요.”
- “짧게 기록해도 괜찮아요.”
- “한 줄의 기록이 나중에 큰 힌트가 돼요.”

---

### D. 통증 / 불편 체크
**사용 캐릭터**
- `어깨_통증을_호소하는_귀여운_마스코트.png`

**언제 쓰나**
- 오늘의 몸에서 통증 위치 입력할 때
- 불편 강도 체크
- 특정 부위 상태가 반복 기록될 때

**추천 문구 예시**
- “어느 부위가 가장 불편한가요?”
- “불편 정도를 가볍게 체크해보세요.”
- “기록을 남기면 반복 패턴을 확인할 수 있어요.”

**주의**
- 너무 아프거나 과장된 표정으로 쓰지 않는다.
- 공포/위기 느낌이 아니라 **공감과 체크 유도** 중심으로 사용한다.

---

### E. 수면 / 회복 / 휴식
**사용 캐릭터**
- `잠든_초록_가방_마스코트.png`

**언제 쓰나**
- 수면 기록 화면
- 회복 루틴 추천
- 휴식이 필요한 날의 가이드
- 오늘 컨디션이 낮은 날

**추천 문구 예시**
- “오늘은 회복이 먼저예요.”
- “수면과 휴식도 중요한 기록이에요.”
- “충분히 쉬는 것도 몸을 돌보는 방법이에요.”

---

### F. 챗 / 코칭 / 설명
**사용 캐릭터**
- `클립보드를_든_귀여운_상담_마스코트.png`

**언제 쓰나**
- AI 설명
- 루틴 추천 이유 안내
- 기록 방법 소개
- 질문/답변 화면
- Empty state에서 무엇을 해야 하는지 설명할 때

**추천 문구 예시**
- “기록을 바탕으로 오늘의 루틴을 제안할게요.”
- “지금 상태에 맞는 관리 포인트를 함께 볼까요?”
- “궁금한 점이 있다면 가볍게 물어보세요.”

---

### G. 패턴 분석 / 최근 변화 / 인사이트
**사용 캐릭터**
- `돋보기_든_귀여운_탐정_마스코트.png`

**언제 쓰나**
- 최근 변화 화면
- 커넥션 뷰
- 패턴 분석 결과
- 반복되는 통증/수면/걸음 수 흐름을 보여줄 때

**추천 문구 예시**
- “기록 사이의 변화를 살펴보고 있어요.”
- “최근 몸 상태의 흐름이 조금씩 보이고 있어요.”
- “반복되는 패턴을 함께 찾아볼까요?”

**주의**
- 재미 요소보다 **‘발견’과 ‘이해’**의 톤으로 사용한다.
- 너무 탐정/게임 느낌으로 과하게 쓰지 않는다.

## 5. 추천 배치 규칙

### 권장 크기
- 카드/Empty state: **80~120px**
- 큰 안내 화면: **120~160px**
- 작은 보조 안내: **48~64px**

### 권장 위치
- 카드 상단 또는 좌측
- 빈 화면 중앙 상단
- 설명 문구 위
- 사용자가 “무엇을 해야 하는지” 이해해야 하는 위치

### 피해야 할 사용
- 데이터 카드마다 캐릭터를 전부 붙이는 것
- 탭바 아이콘처럼 항상 노출되는 사용
- 경고/에러/의료 진단처럼 무거운 의미 전달
- 너무 많은 모션/이펙트와 함께 과도하게 사용하는 것

## 6. Claude Code 전달용 구현 가이드

아래 내용을 그대로 Claude Code에 전달해도 됩니다.

### 구현 목표
- 하음 서비스의 캐릭터 **체키**를 상태별로 UI에 노출한다.
- 캐릭터는 장식이 아니라 **상태 전달용 보조 요소**로 사용한다.
- 각 화면에서 문맥에 맞는 캐릭터만 선택적으로 노출한다.

### 상태별 매핑
```ts
const chekiAssets = {
  base: "라임_가방을_멘_귀여운_마스코트.png",
  welcome: "초록_가방을_멘_귀여운_손인사_캐릭터.png",
  sleep: "잠든_초록_가방_마스코트.png",
  painCheck: "어깨_통증을_호소하는_귀여운_마스코트.png",
  chat: "클립보드를_든_귀여운_상담_마스코트.png",
  recording: "메모하는_귀여운_라임_마스코트.png",
  insight: "돋보기_든_귀여운_탐정_마스코트.png",
};
```

### 추천 노출 로직
```ts
if (screen === "onboarding") use("welcome");
if (screen === "home" && !hasTodayRecord) use("welcome");
if (screen === "record") use("recording");
if (screen === "pain-check") use("painCheck");
if (screen === "sleep") use("sleep");
if (screen === "chat" || screen === "guide") use("chat");
if (screen === "insight" || screen === "connection") use("insight");
```

### 구현 원칙
- 배경은 투명 PNG를 유지한다.
- 캐릭터 크기는 화면 목적에 따라 48~160px 범위에서 사용한다.
- 데이터/텍스트가 메인인 화면에서는 캐릭터를 보조 요소로만 둔다.
- 홈/온보딩/Empty state에서 가장 적극적으로 사용한다.

## 7. 향후 추가 권장 사항

현재 세트만으로도 기본 적용은 가능하지만, 실제 서비스 완성도를 높이려면 아래를 추가하는 것이 좋습니다.

### 추가 제작 권장 상태
- `complete` : 기록 완료 / 루틴 완료용 성공 상태
- `neutral` : 아무 소품 없이 서 있는 진짜 기본형
- `empty` : 기다리는 느낌의 대기 상태
- `encourage` : 가볍게 응원하는 상태

### 파일 포맷 권장
- 최종 서비스 적용용: **투명 PNG**
- 디자인 시스템/확장성 고려: **SVG 버전도 병행 제작**
- 파일명은 영문 키 기반으로 정리 권장
  - `cheki-welcome.png`
  - `cheki-sleep.png`
  - `cheki-pain-check.png`
  - `cheki-chat.png`
  - `cheki-recording.png`
  - `cheki-insight.png`

## 8. 최종 정리

체키는 하음 서비스에서 아래 역할을 맡는다.

- **환영한다** → `welcome`
- **기록을 유도한다** → `recording`
- **몸 상태를 공감하며 체크한다** → `painCheck`
- **쉬어야 할 때를 알려준다** → `sleep`
- **설명하고 도와준다** → `chat`
- **쌓인 기록에서 의미를 찾아준다** → `insight`

즉, 체키는 단순히 귀여운 마스코트가 아니라  
**“하루의 몸 기록을 함께 보는 동반자”**로 작동해야 한다.
