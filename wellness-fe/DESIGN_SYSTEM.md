# 몸기록 디자인 시스템

## 서비스 흐름

`오늘 상태 확인 → 기록 → 흐름 발견 → 맞춤 루틴 → 효과 확인 → 전문가 공유`

모든 화면은 현재 단계의 사실, 근거, 다음 행동을 이 순서로 보여준다. 한 화면의 주요 CTA는 하나만 사용한다.

## 색상 역할

- `primary`: 탐색, 선택, 연결, 주요 행동
- `danger`: 불편 부위, 악화, 삭제
- `success`: 기록 완료, 호전
- `warning`: 확인 필요, 안전 안내
- `neutral`: 배경, 구분선, 일반 정보

색은 장식으로 사용하지 않고 텍스트·아이콘·상태 설명과 함께 사용한다. 화면 파일에서 신규 색상을 직접 추가하지 않는다.

## 화면 구조

- 탭 화면: 헤더 → 현재 상태 → 근거 → 다음 행동 → 최근 정보 → 하단 탭
- 입력 화면: 진행률 → 뒤로가기/건너뛰기 → 질문 → 입력 → 고정 CTA
- 상세 화면: 뒤로가기 → 날짜/맥락 → 요약 → 근거 → 관련 행동
- 실행 화면: 종료/건너뛰기 → 현재 동작 → 안내 → 타이머 → 제어

## 시각 규칙

- 모든 기본 화면과 내비게이션 배경은 흰색을 사용한다. 상태색은 선택·경고·주요 행동에만 제한한다.
- 같은 과업은 하나의 표면으로 묶고 카드 격자를 만들지 않는다.
- 구분에는 그림자보다 여백과 구분선을 사용한다.
- 설정·마이·상세 화면은 큰 라운드 카드 대신 제목과 한 줄 목록으로 구성한다.
- 하단 탭은 콘텐츠를 덮지 않으며, 키보드가 열리면 숨겨 입력 영역을 확보한다.
- 제목은 최대 2~3줄, 본문은 최소 12pt를 사용한다.
- 터치 영역은 iOS 44pt, Android 48dp 이상이다.
- 모션은 상태 변화와 공간 이동 설명에만 140~320ms로 사용한다.
- 이모지와 문자 기호를 구조 아이콘으로 사용하지 않는다.

## 코드 규칙

- 색상, 간격, 반경, 타이포, 모션은 `src/theme/tokens.ts`에서만 정의한다.
- 조회 화면은 로딩·오류·빈 상태를 분리한다.
- 저장 화면은 중복 제출 방지, 실패 후 입력 보존, 인접 오류를 제공한다.
- API 응답은 도메인 타입을 거쳐 UI 의미로 변환한다.

## 적용 범위

- 인증: 스플래시, 로그인, 회원가입
- 온보딩: 서비스 안내, 동의, 기준선 설정, 건강 데이터 연결
- 기록: 자동 수집 확인, 컨디션, 수면, 불편, 활동·피부, 기록 완료
- 탐색: 홈, 기록 캘린더, 날짜 상세, 커넥션 뷰, 패턴 상세
- 루틴: 오늘의 루틴, 실행 타이머, 완료, 효과 피드백
- 리포트: 요약 설정, 요약 미리보기
- 계정: 마이, 건강 데이터, 알림, 동의·데이터, 계정, 서비스 정보
- 공통: 웰니스 챗, 지속 신호, 로딩·오류·빈 상태

새 라우트는 위 시각 규칙과 하단 고정 요소의 세이프에리아 검사를 통과해야 한다.
