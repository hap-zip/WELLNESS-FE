# 몸기록 디자인 시스템 V4 — Calm Utility

이 문서는 현재 구현의 단일 시각 기준이다. 이전 재설계 문서와 기존 화면은 기능 확인에만 사용하며 시각 설계의 근거로 사용하지 않는다.

## 서비스 흐름

`오늘 기록 → 상태 확인 → 흐름 발견 → 맞춤 루틴 → 효과 확인 → 전문가 공유`

모든 화면은 현재 단계의 사실, 근거, 다음 행동을 이 순서로 보여준다. 한 화면의 주요 CTA는 하나만 사용한다.

## 탭별 역할

- `홈`: 오늘 기록이 없으면 기록 시작만 우선 제시하고, 기록 후에는 오늘 상태·기록 부위·루틴 순으로 보여준다.
- `기록`: 달력에서 날짜를 고르고 원본 기록을 확인한다. 분석이나 발견을 대신하지 않는다.
- `커넥션 뷰`: 같은 기간의 서로 다른 기록을 비교하고 반복 패턴을 확인한다.
- `챗`: 사용자의 기록 또는 공인 의약품 정보를 질문형으로 찾는다. 캐릭터나 AI 홍보를 전면에 두지 않는다.
- `마이`: 계정 현황과 건강 데이터·알림·동의·데이터 관리로 진입한다.

## 강제 원칙

- 기존 JSX 배치에 색상과 반경만 바꾸는 작업을 금지한다.
- 기존 히어로 카드, 반복 카드 목록, 기존 채팅 말풍선 구조를 재사용하지 않는다.
- 기능·데이터·라우트는 보존하지만 화면의 정보 순서와 표현 방식은 새로 설계한다.
- 모든 기본 화면은 흰 배경을 사용하고 정보 묶음은 부드러운 중립 면으로 구분한다.
- 핵심 행동과 선택은 하나의 블루를 사용한다. 빨강·초록·주황은 불편·성공·주의처럼 의미가 있을 때만 쓴다.
- 검은 규칙선, 컬러 레일, 번호 인덱스, 영문 키커로 정보 위계를 만들지 않는다.
- 제목은 24~28pt, 섹션은 20pt를 기본으로 하며 800~900 굵기를 반복하지 않는다.

## 공통 화면 문법

- 탭 화면: 현재 문맥 → 가장 필요한 행동 → 오늘의 상태 → 다음 행동
- 입력 화면: 진행 문맥 → 질문 → 입력 방식에 맞는 전용 컨트롤 → 고정 행동
- 상세 화면: 맥락 → 결론 또는 원본 값 → 근거 장부 → 관련 행동
- 실행 화면: 현재 동작 → 시간 → 자세 → 최소 제어
- 설정 화면: 제목 → 사용자 상태 → 목적별 그룹 → 위험 행동

## 금지 목록

- 같은 크기의 둥근 카드를 무의미하게 반복하는 배치
- 장식용 그라디언트와 글래스 효과
- AI 캐릭터, 상태 점, 반짝임, 과도한 추천 칩
- 영문 눈썹 라벨, 단계 번호 라벨, 목록 앞 01/02 번호, 의미 없는 통계 배지
- 큰 검은 구분선, 답변 왼쪽 컬러 레일, 표처럼 분절된 버튼
- 같은 컴포넌트를 모든 종류의 입력에 강제 적용
- 작은 아이콘 터치 영역과 하단바에 가려지는 입력
- 화면별 임의 색상, 임의 반경, 임의 여백
- 하단 탭은 콘텐츠를 덮지 않으며, 키보드가 열리면 숨겨 입력 영역을 확보한다.
- 제목은 최대 2~3줄, 본문은 최소 12pt를 사용한다.
- 터치 영역은 iOS 44pt, Android 48dp 이상이다.
- 모션은 상태 변화와 공간 이동 설명에만 140~320ms로 사용한다.
- 이모지와 문자 기호를 구조 아이콘으로 사용하지 않는다.

## 코드 규칙

- 색상, 간격, 반경, 타이포, 모션은 `src/theme/tokens.ts`에서만 정의한다.
- 조회 화면은 로딩·오류·빈 상태를 분리한다.
- 저장 화면은 중복 제출 방지, 실패 후 입력 보존, 인접 오류를 제공한다.
- API 응답은 도메인 타입을 거쳐 UI 의미로 변환한다.

## 적용 범위

- 인증: 스플래시, 로그인, 회원가입
- 온보딩: 서비스 안내, 동의, 기준선 설정, 건강 데이터 연결
- 기록: 자동 수집 확인, 컨디션, 수면, 불편, 활동·피부, 기록 완료
- 탐색: 홈, 기록 캘린더, 날짜 상세, 커넥션 뷰, 패턴 상세
- 루틴: 오늘의 루틴, 실행 타이머, 완료, 효과 피드백
- 리포트: 요약 설정, 요약 미리보기
- 계정: 마이, 건강 데이터, 알림, 동의·데이터, 계정, 서비스 정보
- 공통: 웰니스 챗, 지속 신호, 로딩·오류·빈 상태

새 라우트는 이 V4 문서와 하단 고정 요소의 세이프에리아, 키보드, 큰 글자 검사를 통과해야 한다.
