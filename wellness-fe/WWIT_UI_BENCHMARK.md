점검일: 2026-08-06  
대상: [What Was IT](https://wwit.design/) 서비스 목록 전체

## 점검 범위

- 첫 페이지부터 `더보기`를 반복해 마지막 `/page6/`까지 확인했다.
- 서비스 상세 54개를 모두 열고 화면 그룹과 주요 사용자 흐름을 확인했다.
- 각 서비스에서 대표 실제 화면을 1개씩 추출해 54개 화면의 배치, 색, 밀도, 내비게이션을 한 보드에서 육안 대조했다.
- 건강 앱만 고르지 않고 라이프스타일, 금융, 커머스, 부동산, 배달, 엔터테인먼트, 모빌리티를 모두 포함했다.
- 사이트가 제공하는 패턴 18종과 컴포넌트 5종도 제품 화면 점검표에 반영한다.
- WWIT 자료는 과거 앱 버전의 아카이브이므로 한 서비스를 그대로 복제하지 않는다. 다만 정보 우선순위뿐 아니라 타이포 대비, 밀도, 전체 폭 사용, 규칙선, 이미지와 텍스트의 비율, 입력 작업대 등 실제 시각 컴포지션도 분해해 V3에 적극 적용한다.

## 몸기록에 적용할 벤치마크 결론

### 대표 화면 54개 시각 대조 결과

- 흰색 또는 매우 밝은 중립 배경이 가장 보편적이며 브랜드색은 CTA, 선택, 핵심 상태에 제한적으로 쓰였다.
- 홈 상단은 제목·상황 정보와 1~2개의 유틸리티 액션만 두고, 첫 화면에서 가장 중요한 콘텐츠나 행동 하나를 크게 보여줬다.
- 하단 탭은 대부분 4~5개이며 선택한 탭만 색·채움 차이를 주고 바의 장식을 최소화했다.
- 금융처럼 정보량이 많은 앱도 모든 항목을 독립 카드로 만들지 않고 요약 표면 아래에 행 목록과 상세 진입을 사용했다.
- 커머스·콘텐츠 앱은 이미지가 서비스의 핵심일 때만 큰 미디어 영역을 사용하고, 설정·마이·폼 화면에는 장식 이미지를 거의 사용하지 않았다.
- 다크 화면은 수면, 미디어 재생, 특정 브랜드 경험처럼 맥락이 있을 때 선택됐으며 웰니스라는 이유만으로 일괄 적용되지 않았다.
- 일러스트는 온보딩, 프로모션, 빈 상태 설명에 제한적으로 사용됐고 실제 조작 영역을 대신하지 않았다.
- 화면 밀도는 서비스마다 달라도 헤더, 본문 인셋, 탭 높이, 행 간격은 한 서비스 안에서 일관됐다.

### 1. 홈은 대시보드가 아니라 오늘의 출발점

- 기록 전에는 `오늘 기록하기`를 가장 먼저 보여준다.
- 기록 후에는 입력한 상태와 이어서 할 루틴을 먼저 보여준다.
- 과거 차트, 전문가 요약, 설정은 홈에서 상세 정보를 모두 펼치지 않고 해당 탭·상세로 연결한다.
- 참고 구조: 알라미, 플랜핏, 런드리고, 스타벅스, 토스, 카카오 T.

### 2. 기록은 작성과 조회를 분리하되 왕복은 짧게

- 기록 탭의 첫 목적은 날짜별 기록 확인이다.
- 선택 날짜의 핵심 요약과 수정 진입을 같은 화면에 둔다.
- 신규 기록은 단계형 입력을 유지하고 완료 후 선택 날짜 상세로 돌아간다.
- 참고 구조: 플랜핏, 필라이즈, 밀리의 서재, 세탁특공대, 미소.

### 3. 커넥션 뷰는 차트보다 해석이 먼저

- 개인 기준선과 이번 기간의 변화 문장을 먼저 제시한다.
- 동시에 비교할 지표는 최대 3개로 제한한다.
- 날짜를 선택하면 모든 차트와 날짜 상세가 함께 갱신된다.
- 색만으로 계열을 구분하지 않고 선 형태, 라벨, 값 표기를 함께 사용한다.
- 참고 구조: 플랜핏, 뤼이드 튜터, 필라이즈, 호갱노노, 토스, 뱅크샐러드, 코인원.

### 4. 루틴은 실행 상태를 잃지 않게 한다

- 시작 전에는 소요 시간과 구성, 실행 중에는 남은 시간과 다음 단계, 완료 후에는 변화 기록을 보여준다.
- 앱이 백그라운드로 이동해도 진행 상태가 유지되는 구조를 전제로 한다.
- 참고 구조: 플랜핏, 알라미, FLO, 미소, 세탁특공대.

### 5. 챗은 AI 제품처럼 보이지 않는 기록 보조 대화

- 로봇 캐릭터, 광택 그라데이션, 과도한 추천 카드, `AI가 분석했어요` 같은 장식을 사용하지 않는다.
- 일반 메신저를 그대로 복제하지 않는다. 사용자 질문은 짧은 블록, 서비스 답변은 편집형 본문, 근거는 장부 행으로 분리한다.
- 입력창은 키보드와 하단 탭의 안전 영역을 항상 피한다.
- 참고 구조: 당근마켓의 채팅, 트로스트의 민감 정보 문장, 뤼튼의 입력 흐름만 제한적으로 사용한다.

### 6. 마이는 프로필 카드보다 계정·설정 탐색이 우선

- 큰 장식형 프로필 카드를 제거하고 이름·계정 정보는 간결한 헤더로 축소한다.
- 건강 데이터, 알림, 동의·데이터, 계정 관리를 구분된 행 목록으로 구성한다.
- 위험 작업은 별도 상세 화면과 재확인을 사용한다.
- 참고 구조: 토스, 네이버페이, KREAM, LG ThinQ, 스타벅스, 카카오페이.

### 7. 온보딩과 권한은 필요한 순간에 요청

- 이용약관, 개인정보, 건강정보 동의를 분리한다.
- 알림, 사진, 건강 데이터 OS 권한은 해당 기능 진입 시 목적을 설명한 뒤 요청한다.
- 거부해도 앱 핵심 기록 기능은 사용할 수 있고 설정 이동 경로를 제공한다.
- 참고 구조: 알라미, 플랜핏, LG ThinQ, 토스, 카카오페이.

## 채택하지 않을 패턴

- 홈에 모든 기능을 동일 크기 카드로 나열하는 대시보드
- 모든 표면에 큰 반경과 그림자를 적용하는 생성형 UI 스타일
- 보라색·청록색 그라데이션과 의미 없는 빛 효과
- 영문 장식 라벨, 로봇 캐릭터, 반짝임 아이콘 등 AI 서비스 관습
- 데이터가 없는데 샘플 수치나 정상 상태처럼 보이는 결과를 표시하는 방식
- 탭 바와 고정 CTA가 입력창·목록 마지막 항목을 가리는 배치
- 건강 상태를 빨강·초록 색 하나로만 표현하는 방식
- 한 화면에 4개 이상의 차트 또는 3개를 넘는 시계열을 동시에 표시하는 방식

## 구현 전 화면 재설계 순서

1. 전역 셸: 흰 배경, 헤더, 하단 탭, 세이프에리아, 화면 인셋
2. 홈: 기록 전·후·실패 상태와 오늘의 단일 핵심 행동
3. 기록: 캘린더, 날짜 상세, 데일리 체크 단계, 완료·수정
4. 커넥션 뷰: 기준선, 기간·지표 선택, 차트, 날짜 상세
5. 루틴·피드백·지속 신호: 준비, 실행, 완료, 다음 날 확인
6. 챗: 대화 목록, 메시지 상태, 첨부, 키보드·탭 안전 영역
7. 마이·설정: 계정, 건강 데이터, 알림, 동의·데이터, 위험 작업
8. 인증·온보딩·권한: 입력, 동의, 연결, 건너뛰기, 복귀
9. 전 화면 상태: 로딩, 빈 상태, 오류, 재시도, 오프라인, 권한 거부
10. 실기기 검수: 작은 iPhone, 큰 iPhone, Android, 큰 글자, 감소된 모션

## 출시 품질 공통 기준

- 화면 배경은 기본 흰색이며 표면 구분이 필요할 때만 중립 배경·테두리를 사용한다.
- 색상은 정보 의미와 행동 상태에만 사용하고 장식 목적으로 확대하지 않는다.
- 최소 터치 영역은 iOS 44pt, Android 48dp다.
- 4/8pt 간격 체계와 의미 기반 토큰을 사용한다.
- 로딩, 빈 데이터, 오류, 권한 거부를 서로 다른 상태로 렌더링한다.
- 고정 헤더·탭·CTA·입력창은 상하단 세이프에리아와 키보드를 침범하지 않는다.
- 네트워크 응답 타입과 화면 컴포넌트를 분리해 목업을 실제 API 구현체로 교체할 수 있게 한다.
- 모션은 상태 전환을 설명할 때만 150~300ms로 사용하고 감소된 모션 설정을 존중한다.
