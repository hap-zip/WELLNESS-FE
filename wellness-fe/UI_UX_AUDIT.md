# 몸기록 V3 UI·UX 감사

점검일: 2026-08-09

## 결론

전체 출시 라우트에 V3 코드 교체를 반영했고 TypeScript, ESLint, iOS 정적 export를 통과했다. 다만 화면 존재와 정적 통과는 디자인 승인의 근거가 아니므로 실제 기기 캡처 승인 전까지 최종 완료 판정은 보류한다.

## 발견된 재발 원인

- V2 문서와 완료 체크가 동시에 살아 있었다.
- 기능 구현 체크와 디자인 승인 체크를 같은 `[x]`로 관리했다.
- 토큰 교체와 JSX 재배치를 전면 재설계로 판정했다.
- 홈을 먼저 수정한 뒤 상세 화면은 공통 스타일만 바꿨다.
- 채팅에서 기존 메시지 구조를 유지한 채 색상과 여백만 변경했다.

## V3 감사 규칙

- 기능 골격과 디자인 상태를 별도 열로 관리한다.
- 기존 JSX 정보 순서를 그대로 사용하면 미적용으로 판정한다.
- 페이지마다 핵심 장면과 시선 흐름을 설명할 수 있어야 한다.
- 모든 화면이 같은 카드·같은 헤더를 사용한다고 일관된 디자인으로 판정하지 않는다.
- 채팅은 AI 캐릭터와 템플릿 말풍선이 없어도 일반 메신저를 복제하면 미완료다.
- 실제 기기 캡처 승인 전에는 `디자인 완료`를 표시하지 않는다.

## API와 UI 경계

- 화면은 `wellnessApi`와 도메인 타입만 사용한다.
- API 값이 색상, 여백, 아이콘, 반경을 직접 결정하지 않는다.
- 로딩·빈·오류 상태는 서비스 계층이 아니라 화면의 V3 컴포지션으로 표현한다.
- UI 교체 중에도 입력값, 저장 실패 복구, 날짜 선택, 사진, 타이머 상태를 보존한다.
