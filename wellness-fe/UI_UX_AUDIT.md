# 몸기록 UI·UX 구현 기준과 감사 결과

점검일: 2026-08-05

## 제품 디자인 원칙

- 몸기록은 진단 앱이 아니라 사용자가 몸과 생활의 흐름을 차분하게 이해하도록 돕는 기록 서비스다.
- 첫 화면에서 장식보다 `오늘 상태 → 근거 → 다음 행동`의 순서가 먼저 보여야 한다.
- 건강 상태는 색만으로 구분하지 않고 부위명, 강도, 변화 문장을 함께 표시한다.
- 카드 수를 늘려 정보를 분절하지 않는다. 같은 과업의 정보는 하나의 표면 안에서 계층으로 정리한다.
- 보라색 그라데이션, 과도한 둥근 카드, 불필요한 영문 메타 라벨, 문자·이모지 아이콘 등 전형적인 생성형 UI 표현을 사용하지 않는다.
- 움직임은 상태 변화와 공간 이동을 설명할 때만 160~240ms로 사용하고 감소된 모션 설정을 존중한다.

## 데이터·API 설계 원칙

- 화면은 `wellnessApi`의 인터페이스와 `src/domain/wellness.ts`의 응답 타입만 사용한다.
- 목업 응답도 실제 API가 반환할 식별자, 날짜, 상태, 표시 문구 구조를 따른다.
- 조회 화면은 로딩, 성공, 빈 데이터, 실패와 재시도를 서로 다른 상태로 렌더링한다.
- 저장 화면은 중복 제출 방지, 진행 상태, 필드 인접 오류, 실패 후 입력 보존을 제공한다.
- API 교체 시 JSX나 스타일을 수정하지 않고 서비스 구현체만 바꿀 수 있어야 한다.
- 서버 값으로 색상·간격·아이콘 이름을 직접 전달하지 않는다. 서버 상태를 도메인 상태로 변환한 뒤 UI 토큰에 매핑한다.

## 완료 조건

- iPhone 소형 화면, 대형 화면, 가로 모드에서 주요 정보와 CTA가 잘리지 않는다.
- 모든 터치 영역이 iOS 44pt, Android 48dp 이상이다.
- VoiceOver/TalkBack이 화면 순서대로 의미 있는 라벨을 읽는다.
- Dynamic Type 확대와 감소된 모션 설정에서 과업을 완료할 수 있다.
- 로딩·오류·빈 상태를 실제 서비스 구현체 교체 없이 테스트할 수 있다.
- `npx tsc --noEmit`, `git diff --check`, iOS Expo export가 통과한다.
