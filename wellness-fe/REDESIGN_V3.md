# 몸기록 UI 전면 재설계 V3

## 선언

V3는 기존 UI의 색상 변경이나 카드 정리가 아니다. 기존 화면의 히어로, 카드, 말풍선, 섹션 배치와 시각적 문법을 설계 참고 대상으로 사용하지 않는다. 기능, 데이터 계약, 라우트만 보존하고 화면은 빈 캔버스에서 다시 설계한다.

다음 표현은 작업 완료로 인정하지 않는다.

- 기존 JSX 순서를 유지한 채 배경색과 테두리만 변경
- 모든 콘텐츠를 둥근 카드에 넣는 방식
- 기능과 무관하게 같은 색과 같은 컴포넌트를 반복
- AI 캐릭터, 반짝임, 상태 점, 과도한 추천 칩으로 챗봇임을 강조
- 모바일이라는 이유로 웹·편집 디자인의 레이아웃 원리를 배제
- 기존 화면과 비슷하다는 이유로 기능을 삭제하거나 이름을 변경

## 제품의 시각적 정의

몸기록은 건강 대시보드가 아니라 개인의 몸 상태를 쌓아 읽는 기록 도구다. 화면은 병원 시스템처럼 차갑거나 AI 서비스처럼 장식적이지 않아야 한다. 종이 기록지의 읽기 쉬움, 국내 생활 앱의 빠른 조작, 편집 디자인의 강한 정보 위계를 결합한다.

핵심 흐름은 `기록 → 확인 → 연결 → 실행 → 회고`다. 각 화면은 이 흐름에서 자신의 역할 하나를 먼저 보여준다.

## 벤치마크 적용 방식

### 29CM

- 넓은 여백과 강한 제목 대비
- 카드 대신 이미지, 문장, 구분선으로 만드는 계층
- 인증·마이·긴 문서 화면의 편집형 구성

### 토스·네이버페이

- 한 화면의 핵심 숫자 또는 문장을 먼저 제시
- 상세 정보와 설정은 예측 가능한 목록으로 분리
- 상태와 행동을 한 줄 안에서 명확히 구분

### 오늘의집·당근

- 콘텐츠 맥락을 잃지 않는 하단 입력과 탐색
- 사용자의 콘텐츠가 서비스 장식보다 앞서는 구조
- 익숙한 메시지·첨부·목록 조작 방식

### 필라이즈·플랜핏

- 서로 다른 건강 입력을 같은 카드로 강제하지 않는 방식
- 준비·실행·완료 상태에 따라 화면 밀도를 바꾸는 방식
- 데이터 출처와 사용자가 입력한 값을 구분하는 방식

벤치마크는 색상표를 복사하는 작업이 아니다. 정보 우선순위, 시선 이동, 한 화면의 행동 수, 콘텐츠 밀도와 전환 방식을 몸기록에 맞게 재구성한다.

## 새 시각 언어: Editorial Ledger

### 기본 원칙

- 기본 배경은 흰색이다.
- 화면은 `상단 문맥 → 핵심 문장 → 기록 본문 → 다음 행동`의 세로 장부 구조를 사용한다.
- 큰 둥근 카드 대신 전체 폭 밴드, 얇은 규칙선, 컬럼, 인덱스 행을 사용한다.
- 반경은 입력·선택·모달처럼 경계가 필요한 요소에만 사용한다.
- 주요 화면마다 하나의 시각적 장면을 만든다. 같은 히어로를 복제하지 않는다.
- 기능별 색은 장식이 아니라 현재 작업의 문맥을 표시한다.

### 색상

| 역할 | 값 | 용도 |
|---|---|---|
| Ink | `#111827` | 제목, 본문, 주요 행동 |
| Paper | `#FFFFFF` | 기본 화면 |
| Wash | `#F3F5F8` | 편집 밴드, 데이터 그룹 |
| Rule | `#D8DDE6` | 구분선 |
| Cobalt | `#2856D8` | 탐색, 연결, 수면, 데이터 |
| Vermilion | `#E75B45` | 몸 상태, 불편, 기록 |
| Pine | `#17745B` | 루틴, 회복, 완료 |
| Amber | `#A56322` | 확인 필요 |
| Red | `#B63D43` | 위험, 삭제 |

색면 비율은 흰색 82%, 중립 10%, 기능색 전체 8% 이하를 기본으로 한다.

### 타이포

- 화면 제목: 32/39, 800
- 핵심 상태 문장: 26/34, 800
- 섹션 제목: 18/25, 800
- 기본 본문: 15/23, 400
- 메타 정보: 12/18, 600
- 제목은 최대 2줄이며 장식용 영문 라벨과 단계 번호 라벨을 사용하지 않는다.

### 모션

- 화면 진입 시 핵심 문장과 첫 콘텐츠를 40~60ms 간격으로 순차 노출한다.
- 목록 선택은 색상·규칙선·아이콘 상태가 180~240ms 안에서 전환된다.
- 차트는 진입 시 선과 막대가 실제 값까지 그려진다.
- 모션은 위치 관계와 상태 변화를 설명할 때만 사용하며 reduced motion을 존중한다.

## 채팅 전면 교체

기존 채팅의 헤더, 인사 말풍선, 추천 질문 카드, 둥근 입력창 구성을 폐기한다.

### 새 구조

1. 상단에는 `웰니스 챗`과 기록 참조 범위, 기록 요약 진입만 둔다.
2. 대화가 없을 때는 캐릭터 대신 큰 질문 제목과 기록 기반 시작 문장을 보여준다.
3. 추천 질문은 칩이 아니라 세로 인덱스 목록으로 제공하고 누르면 즉시 질문으로 전환한다.
4. 사용자 메시지는 오른쪽의 짧은 잉크 블록으로 표시한다.
5. 답변은 말풍선을 사용하지 않고 본문과 얇은 코발트 인용선으로 표시한다.
6. 답변 근거는 `참고한 기록` 장부 행으로 분리한다.
7. 의약품 정보는 대화 말풍선이 아니라 출처가 명확한 정보 시트로 표시한다.
8. 입력 영역은 하단 고정 작업대로 구성한다. 사진 첨부, 실제 입력, 전송을 한 줄에 두고 키보드·탭·홈 인디케이터와 겹치지 않는다.
9. 로딩은 AI 애니메이션이 아니라 `기록을 읽는 중` 텍스트와 짧은 진행선으로 표시한다.

## 전체 화면 교체 지도

### 인증·온보딩

- 스플래시: 로고 카드 제거, 타이포 중심의 짧은 브랜드 장면
- 로그인·회원가입: 중앙 카드 제거, 편집형 제목과 하단 행동 영역
- 온보딩: 기능 카드 나열 제거, 기록이 쌓이는 3개의 장면
- 동의·연동: 약관과 권한을 장부형 목록으로 분리

### 홈

- 기존 히어로 카드 제거
- 날짜와 알림 아래 오늘 기록 여부를 하나의 강한 문장으로 제시
- 전신 맵과 실제 기록 정보를 한 장면으로 결합
- 기록 전에는 기록 시작이 먼저, 기록 후에는 확인과 루틴이 먼저 보이게 상태별 구성을 변경
- 최근 기록은 카드가 아니라 날짜 인덱스 목록으로 표시

### 기록 입력

- 모든 단계에 같은 선택 카드 사용 금지
- 컨디션은 세로 척도, 수면은 연결 척도와 자세 이미지, 불편은 전신 선택, 활동은 설명형 목록, 피부는 태그·사진 작업대로 구분
- 하단 CTA는 키보드와 세이프에리아를 피하고 실패 시 입력을 보존

### 기록·커넥션

- 캘린더와 날짜 요약은 하나의 카드 안에 넣지 않는다.
- 날짜 상세는 수면·불편·활동·피부 원본 값을 장부 섹션으로 표시한다.
- 커넥션 뷰는 기간, 지표, 차트, 선택 날짜 값을 하나의 분석 캔버스로 구성한다.
- 패턴 상세는 결론, 근거, 행동 순으로 배치한다.

### 루틴·피드백

- 준비는 편집형 운동 처방지, 실행은 별도의 집중 모드, 완료는 결과 영수증 구조를 사용한다.
- 효과 피드백은 완료 흐름과 시각적으로 연결한다.
- 지속 신호는 경고 카드가 아니라 발생 이유와 대응 행동을 명확히 나눈다.

### 마이·설정·리포트

- 프로필 카드 제거, 이름과 사용 현황을 페이지 헤더에 통합
- 메뉴는 목적별 인덱스 목록으로 구성
- 설정 토글, 권한, 데이터 삭제의 상태와 위험도를 시각적으로 분리
- 리포트는 앱 카드가 아니라 공유 가능한 편집 문서처럼 구성

## 기능 보존 규칙

라우트, API 어댑터, 저장 상태, 오류 복구, 사진 첨부, 차트 선택, 날짜 선택, 타이머, 알림 설정, 데이터 관리 기능은 삭제하지 않는다. UI 구조 변경 때문에 기능이 가려지거나 접근 단계가 늘어나는 것도 기능 손실로 본다.

## 완료 기준

- 모든 라우트가 V3 토큰과 V3 화면 문법을 사용한다.
- 기존 V2 카드·히어로·챗 말풍선 구조가 남아 있지 않다.
- 375pt, 작은 화면, 큰 글자, 키보드, 세이프에리아를 확인한다.
- 로딩·오류·빈 상태가 실제 화면의 위계와 동일하다.
- TypeScript, ESLint, iOS 번들이 통과한다.
- 실제 기기 시각 QA 전에는 출시 가능 상태로 표현하지 않는다.
